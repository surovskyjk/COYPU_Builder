# T-114 — Protocol surface for runs, catalogue and `.coypu` import

**Milestone:** P1.M1 · **Retires debt:** D3 (final) · **Depends on:** T-101, T-111, T-113 · **Blocks:** T-115

## Context

`run.get` is a stub that raises `E_NOT_FOUND`. After T-111 and T-113 the backend knows how to normalise a
COYPU run and load a vehicle catalogue, but none of it reaches the client. This task opens the wire surface
that M2's playback needs: import a `.coypu` archive or a kinematics CSV, list the runs it produced, fetch one
as baked blobs, and fetch the catalogue and an assembled consist.

T-101 turned the method table into data. Every method added here goes into `METHODS`, and
`docs/protocol/ipc.md` regenerates — the CI gate makes that non-optional.

## Contract

### Session state

```python
@dataclass
class RunEntry:
    run: KinematicsRun
    source: str                  # "coypu" | "csv"
    alignment_id: EntityId | None = None
    trainset_id: EntityId | None = None

@dataclass
class ProjectState:
    ...                          # existing fields unchanged
    runs: dict[str, RunEntry] = field(default_factory=dict)
    trainsets: dict[str, Trainset] = field(default_factory=dict)
    stops: tuple[Stop, ...] = ()
```

The catalogue is process-wide and immutable; load it once (module-level or on first use), not per session.

### Methods

**`import.coypu`** — read a `.coypu` archive: parse its embedded `assets/*.xml` LandXML through the existing
reader to obtain alignments, normalise every kinematics run, read the stops, and import the vehicle. One call,
because that is how a user thinks about opening a COYPU project.

```python
class ImportCoypuParams(msgspec.Struct, frozen=True):
    path: str
    crs: str | None = None

class ImportCoypuResult(msgspec.Struct, frozen=True):
    alignments: tuple[AlignmentSummary, ...]
    runs: tuple[RunSummary, ...]
    trainsets: tuple[TrainsetSummary, ...]
    stops: tuple[StopDTO, ...]
    warnings: tuple[str, ...] = ()
```

If the archive has no embedded LandXML asset, that is `E_EMPTY` with a message that says so — do not fall
back to reconstructing geometry from the stored `denseAlignment` arrays.

**`import.kinematics`** — a standalone CSV in either dialect, attached to an already-imported alignment.

```python
class ImportKinematicsParams(msgspec.Struct, frozen=True):
    path: str
    alignment_id: str | None = None
    stops_path: str | None = None

class ImportKinematicsResult(msgspec.Struct, frozen=True):
    runs: tuple[RunSummary, ...]
    stops: tuple[StopDTO, ...]
    warnings: tuple[str, ...] = ()
```

**`run.list`** → `RunListResult(runs: tuple[RunSummary, ...])`, no blobs.

```python
class RunSummary(msgspec.Struct, frozen=True):
    run_id: str
    name: str
    alignment_id: str | None
    trainset_id: str | None
    direction: int
    station_start: float
    station_end: float
    duration_s: float
    sample_count: int
    stop_count: int
    warnings: tuple[str, ...] = ()
```

**`run.get`** — replaces the stub. Returns metadata plus the baked table as blobs.

```python
class RunGetParams(msgspec.Struct, frozen=True):
    run_id: str
    dt: float = 0.05

class RunGetResult(msgspec.Struct, frozen=True):
    run_id: str
    dt: float
    row_count: int
    duration_s: float
    direction: int
    stops: tuple[StopDTO, ...]
```

Blobs, in this emission order — the tail is concatenated in dict order, so the order is contractual:
`station <f4 (n,)`, `speed <f4 (n,)`, `accel <f4 (n,)`, then `f_traction`, `f_braking`, `f_resistance`
(`<f4 (n,)`, each **omitted entirely** when the source had none, never sent as zeros). There is no `time`
blob: the table is time-uniform, so the client reconstructs `t = i·dt`. Say this explicitly in the
`BlobSpec` descriptions so no client author goes looking for it.

**`catalogue.vehicles`** → `CatalogueVehiclesResult(vehicles: tuple[VehicleSpecDTO, ...])`. A flat JSON
projection of `VehicleSpec` including cars and dynamics; no blobs.

**`trainset.get`** → the assembled consist for a `trainset_id`, as `TrainsetDTO` with resolved cars. No
poses: ADR 0007 puts posing in the client, and T-112's backend chain is a reference only.

```python
class TrainsetGetParams(msgspec.Struct, frozen=True):
    trainset_id: str

class TrainsetCreateParams(msgspec.Struct, frozen=True):
    spec_key: str
    units: int = 1
    name: str = ""
```

Include `trainset.create` so the client can assemble a consist from a catalogue key when an import did not
supply one — it is three lines on top of `Trainset.from_spec` and M2 needs it.

### DTO discipline

`protocol/` types are wire types and must not be domain dataclasses re-exported. Convert explicitly:
`StopDTO`, `VehicleSpecDTO`, `CarSpecDTO`, `TrainsetSummary`, `TrainsetDTO`. Domain objects never cross the
boundary — `server/` is the only layer that knows the wire format, and `domain/` must remain importable with
msgspec absent.

### Precision on the wire

float32 for every blob (ADR 0004), float64 stays in the domain. Station values reach ~18 000 m on the Kralupy
fixture, where float32 resolves to about 1 mm — acceptable for a run table, and the client uses it for
lookup, not for geometry. Note it in the `BlobSpec` description.

## Invariants

- **ADR 0003:** `METHODS` is the single source of truth; `docs/protocol/ipc.md` regenerates and CI gates it.
- **ADR 0007:** no method here is on a per-frame path. `run.get` is called once per run, not once per frame.
  Do not add a "pose at time t" method, however convenient it would be for a first demo.
- **`domain/` stays pure** — no msgspec import beneath `domain/`.
- **Layering:** `io/` converts formats ⇄ domain; `server/` converts domain ⇄ wire. A handler that parses a
  CSV itself is in the wrong layer.
- Existing methods keep their wire shapes. The Godot suite from T-102 must pass unmodified.

## Acceptance criteria

1. `import.coypu` on `backend/tests/fixtures/kralupy/kralupy_neratovice_092.coypu` returns one alignment, at
   least one run, the six stops, and a trainset, with no warnings that indicate data loss.
2. `run.list` then `run.get` returns blobs whose lengths all equal `row_count`, and `row_count · dt`
   reproduces `duration_s` to within one `dt`.
3. Force blobs are absent — not zero-filled — for a run whose source lacked them, and the result's `blobs`
   list reflects that.
4. `run.get` with an unknown `run_id` returns `E_NOT_FOUND`; with `dt <= 0` returns `E_BAD_PARAMS`.
5. `import.kinematics` with a CSV in each dialect produces equivalent `RunSummary` values.
6. `catalogue.vehicles` returns all three catalogue entries including the tram.
7. `trainset.create` with `units=2` then `trainset.get` returns the doubled consist.
8. `METHODS` and `DISPATCH` still agree (T-101's test), and
   `uv run python ../tools/gen_protocol_docs.py --check` exits 0 with the regenerated file committed.
9. A full round trip over a real WebSocket in `test_server_smoke.py` style covers `import.coypu` → `run.list`
   → `run.get` and asserts blob dtypes and shapes.
10. The Godot suite passes unmodified.
