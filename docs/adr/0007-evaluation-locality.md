# ADR 0007 — Per-frame evaluation happens in the client from baked tables

Status: accepted (2026-09-06)

## Decision

- The backend bakes alignments into dense `FrameTable`s (station, position, basis, cant, gradient,
  curvature, segment index — `domain/sampling.py`) and kinematics into `RunTable`s (time, station, speed, …).
- The client evaluates vehicle poses, camera follow and timeline scrubbing by interpolating those tables at
  60 Hz. No RPC is ever issued from `_process`.
- Editing (Phase 2) returns span-local deltas of the affected tables, mirroring the proven span-rebuild
  pattern from COYPU Feeder; the client patches only the changed range.
- Algorithms duplicated on both sides (frame interpolation, trainset chain) are validated against
  `shared/golden/*.json` generated by the backend.

## Consequences

Latency on the IPC path affects only command round-trips, never playback smoothness.

Terrain display tiles (T-132, 2026-10-08) are heightfields: the backend sends float32 heights on a regular
lattice, relative to a tile origin. The client builds the triangles and derives normals. This is
connectivity over heights the backend owns, in the same way that sleeper placement is an evaluation of
backend tables. It costs about a tenth of the traffic of shipping vertex buffers. Every ground *query* still
goes to the backend's analysis surface, never to the tiles.
